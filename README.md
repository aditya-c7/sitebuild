# Adityahq — Developer Portfolio

Aditya Chitragar's developer portfolio — Next.js + TypeScript + Tailwind.

## Quick commands

```bash
npm install              # install dependencies
npm run dev              # start the dev server
npm run build            # production build
npm run start            # serve the production build
npm run typecheck        # TypeScript checks (tsc --noEmit)
npm run phones:generate  # regenerate the Android phone marketing-name dataset
```

`npm run phones:generate` runs `scripts/generate-phone-models.mjs`, which rebuilds
`src/data/generated/androidPhoneModels.json` from Google's official Play
supported-device catalog. Run it manually whenever you want fresh device data
(newly released phones); it is never triggered by `build`/`prebuild`.

## Visitor phone-name detection (mobile only)

- The marketing-name dataset is generated by `scripts/generate-phone-models.mjs` from
  Google's official Play supported-device catalog
  ([supported_devices.html](https://storage.googleapis.com/play_public/supported_devices.html),
  [device program help page](https://support.google.com/googleplay/answer/1727131)).
  It covers Android phones by exact model code and should be regenerated periodically
  for newly released devices.
- Phone names come ONLY from `navigator.userAgentData.getHighEntropyValues(["model", …])`
  and an exact, case-sensitive model-code lookup. Browser-reported model availability
  varies by browser and device (Chrome/Samsung Internet expose it; Firefox and
  iOS Safari do not).
- Screen dimensions, aspect ratio, and devicePixelRatio are NEVER used to identify
  or infer a phone name.
- PC and tablet behavior is unchanged: the dataset module is never fetched for them
  (`reportedModel` is only attached for `kind === "mobile"`) and labels keep their
  existing behavior.
- When no model is exposed, or the model code is unmapped/ambiguous, the UI honestly
  shows "Mobile device" — no confidence percentages, no fabricated names.
